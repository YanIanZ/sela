# Security policy

## Supported version

Security fixes are maintained on the default `main` branch. Historical competition snapshots and old deployments are not supported releases. Sela is a prototype.

## Report privately

Use [GitHub private vulnerability reporting](https://github.com/YanIanZ/sela/security/advisories/new) to report a vulnerability or exposed credential. Include affected paths, reproduction steps with synthetic data, expected behavior, and impact. Never include real journal entries, conversations, recovery keys, credentials, or personal information.

Do not disclose exploitable vulnerabilities or sensitive data in public issues. Response and remediation timelines are not guaranteed.

## Scope

Relevant areas include consent enforcement, anonymous-session boundaries, encrypted recovery, forum moderation, crisis handling, model-output validation, rate limits, and deployment configuration. See the [threat model](docs/THREAT_MODEL.md) and [safety policy](docs/SAFETY.md).

For immediate personal danger, contact your local emergency services; GitHub reports are not monitored as an emergency channel.
