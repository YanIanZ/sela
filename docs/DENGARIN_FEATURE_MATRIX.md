### Decision words

| Word | Meaning |
| --- | --- |
| keep | Carry over as is; only the app shell changes |
| improve | Carry over with the stated changes |
| merge | Fold into another v3 feature or into existing v2 code |
| migrate | Rebuild in the v3 Go/React stack, keeping the behaviour that works |
| retire | Not in v3; the code stays in Git history and the archive |
| paused | Not in the pilot; kept in v1 code until cutover and reopened as a backlog item with prerequisites (D-037) |

### Dependencies (two columns)

**v3 surfaces** names the product surfaces a row needs: onboarding, home, conversation, journal, check-in, timeline, memory, consultation summary, preparation & follow-up, reading & support, privacy & data, recipient, platform. **Platform** means persistence, accounts and encryption ([ADR-0002](adr/ADR-0002-persistence-accounts-and-encryption.md), [API v3](API_SPEC_V3.md)), AI routing (D-029), safety, i18n, accessibility and operations.

**Backlog · blockers** names the [backlog](BACKLOG.md) items that carry the row's acceptance criteria, then, after the semicolon, the [blockers](BLOCKERS.md) that stop the row from reaching verified live or a pilot with real users. Work around a blocker continues (blockers, introduction). [Backlog §6](BACKLOG.md#6-feature-matrix-coverage) is the reverse check that every row lands in an item or a recorded retirement; this column can name more items than §6 when one of the row's criteria lives in another item. "—" means a retired row with no item; a cell without a semicolon names no blocker. Each item's own prerequisites are in its "Depends on" line in the backlog. The decisions a row rests on are cited in its Decision column.

### Completion evidence

"none yet" means no v3 evidence exists. A v2 test name means that test already proves the v2 version of the behaviour (memory-only, synthetic, adults, demo scope); v3 must keep it passing or extend it, and it is **not** v3 evidence. Status words are those of [SPEC §G](../SPEC.md#g-goal), their single definition: planned → in progress (work exists on the branch; nothing about it can be claimed yet) → implemented → verified locally → verified live → ready for controlled pilot; "blocked externally" names the blocker. "In progress" in this column is never v3 evidence. Blockers B-1 to B-15 are in [blockers](BLOCKERS.md).

## 4. v1 defects that v3 must not carry over

Paths are V1 paths in this repository; the same code is in D2 and, unless noted, in W. Each guard is a v3 acceptance criterion; none is implemented and none has a **v3 test yet**. The backend parts of the DX-04 and DX-05 guards (per-user encryption, account and guest deletion) are in progress (uncommitted; S-173, S-174); all other guards are **planned**.

| ID | Defect (where) | Why it matters | v3 guard |

| DX-01 | **Pre-consent write.** The landing quick mood creates a session, saves a check-in and awards points before consent, one record per click (`apps/web/src/app/page.tsx:51–66`) | Stores personal data the user never agreed to store | No write of any user content before the storage choice; a test asserts zero rows after a tap without consent (FM-01) |
| DX-02 | **Heavy entries refused.** Journal, check-in, mission, report and assessment block saving while crisis rules match (`apps/web/src/app/journal/page.tsx:57,187`, `apps/web/src/app/checkin/page.tsx:87,263`) | Pushes people to soften what they write; conflicts with listening first | Crisis-matching entries save (when storage is on) with support shown (D-035); a test covers a crisis-matching journal and check-in save (FM-13, FM-17, FM-18) |
