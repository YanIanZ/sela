# Sela v3 accessibility acceptance criteria

Status: **design decision** by the design lead, 2026-10-26, revised after review rounds 1 and 2 ([DESIGN_DIRECTION.md §11](DESIGN_DIRECTION.md#11-revision-log)). **Not implemented and not yet verified.** No screen meets these criteria until the tests and manual reviews described here have been run and their results recorded (P7, P8).

## 1. Target and sources

- **Target:** WCAG 2.2 Level AA (user-confirmed, brief §6).
- **WCAG 2.2:** W3C Recommendation, 12 December 2024 (externally sourced: https://www.w3.org/TR/WCAG22/, fetched 2026-10-26 by discovery).
  - It has **55** success criteria at Level A and AA: **31 at Level A and 24 at Level AA**.
  - 4.1.1 Parsing is obsolete and removed, so it is not a criterion here.
  - Six of the 55 are new in 2.2: 2.4.11, 2.5.7, 2.5.8, 3.2.6, 3.3.7 and 3.3.8.
- **WAI-ARIA 1.2** (W3C Recommendation, 6 June 2023), for live regions:
  - `role="log"` implies `aria-live="polite"`;
  - `role="status"` implies polite and atomic;
  - `aria-busy` is only a "MAY" for assistive technology, so the manual screen-reader tests are mandatory.
- **Discovery basis:** the compliance and accessibility facts report §1. The criteria below make that report specific to the v3 screens in [SCREENS.md](SCREENS.md) and the components in [DESIGN_DIRECTION.md](DESIGN_DIRECTION.md).

## 2. How to read the tables

- **Criterion:** the WCAG number and name.
  - Lvl is the level.
  - **New** marks the six criteria added in 2.2.
  - (cond.) marks a criterion that applies only if the feature exists.
- **Acceptance criterion for Sela:** what must be true. It is written to be testable.
- **Method:**
  - **Auto (rule ids):** axe-core detects most failures with the listed rules. They run under the tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa`.
  - **Scripted:** a Playwright check written for Sela (§6.3). axe cannot test it.
  - **Manual:** a human check using the procedure in §7.
  - Most criteria need more than one method. Automated passes never prove conformance on their own.
- **Screens:** where the risk is highest. Every criterion applies to every screen.

## 5. Specific acceptance criteria

### 5.1 Screen-reader-friendly replies (room, S09)

Replies are **released, not streamed** ([DESIGN_DIRECTION.md §6.5](DESIGN_DIRECTION.md#65-conversation-transcript-messages-composer)): the browser receives a reply only after the server's guards, the one allowed regeneration and, when flagged or the backup model DeepSeek wrote it (ADR-0003 RR-8, §17 O-6), the verifier. The transcript is `role="log"` with `aria-live="off"`, and every announcement comes from the shell regions with fixed text. The criteria below assert **what is heard**, not only how often.

Every ST row is tested by hand on four pairings: **NVDA with Firefox, JAWS with Chrome (or NVDA with Chrome if no JAWS licence is available), VoiceOver with Safari on iOS, and TalkBack with Chrome on Android** (§7.1). The scripted check S-9 asserts the region text for each row.

## 6. Automation plan

Owned by the frontend and e2e engineers (planned).

### 6.1 axe-core

- **Version:** pin to the current release (the facts report saw 4.14.0 as the latest; v2 pins 4.10.3).
- **Tags:** `['wcag2a','wcag2aa','wcag21a','wcag21aa','wcag22aa']`. The v2 e2e lacks `wcag22aa`, so `target-size` never runs (`e2e/journey.e2e.mjs:73`).
- **Schemes:** every scan runs in all four schemes (light, dark, contrast-light, contrast-dark) and once more under `emulateMedia({ forcedColors: 'active' })`.
- **Fail on any violation, at any impact.** v2 failed only on serious or critical (`journey.e2e.mjs:77`).
- **Extra rules:**
  - enable the experimental rules `css-orientation-lock` and `label-content-name-mismatch`;
  - gate on these best-practice rules: `heading-order`, `page-has-heading-one`, `landmark-one-main`, `landmark-unique`, `region`.
- **Review `incomplete` results** in every run report (for example contrast on tints).
- **Do not use `duplicate-id*` as a gate.** Those rules carry only the obsolete `wcag411` tag. Duplicate ids that break references fail under 1.3.1 or 4.1.2 instead.

### 6.2 States to scan

Every route, in each of these:

- the four schemes and forced colours;
- 320px, 320×256 and 1280px;
- text size 150%.

Plus these states:

- **Room:**
  - new, with defaults; new without a storage default (the group error shown);
  - ongoing;
  - **pending** (test double with a slowed release), cold start and checking;
  - released, and released with the `elevated` support line;
  - stopped before release;
  - each withheld notice;
  - crisis panel, condensed panel and the pause line;
  - reflection card, with and without a memory proposal;
  - the contact-detail notice on a sent message;
  - the withheld reply with the in-context checker card;
  - AI unavailable;
  - closing panel, saved and unsaved, and the unsaved-hold warning dialog;
  - the delete confirm with derived items;
  - the typing layout: the composer focused at 360×300 and 320×280, sticky and flow modes, with the pause line shown;
  - the new-content button for a reply and for the crisis panel.

## 7. Manual test procedures

Results are recorded in the owner-testing file (OWNER_TESTER.md, owned by the PM). Agent or automated reviews are not user research and are not independent approval (brief §13).

### 7.1 Screen-reader procedure (per platform)

**Platforms:** NVDA with Firefox; JAWS with Chrome (or NVDA with Chrome); VoiceOver with Safari on iOS; TalkBack with Chrome on Android. Android is the priority for Indonesia.

1. Sign in, once with a wrong password: the alert line is heard, then the username field with the same message; the password is still in its field.
2. Open the room.
3. Send a message. Its text must **not** be read back.
4. Listen: one "Sela sedang menulis…", then one "Sela: ⟨reply⟩" with nothing after it ("Umumkan balasan ke pembaca layar" on). Note anything extra that is heard (author line, provider, buttons) as a failure of ST-2. Ask in English in the Indonesian interface: the reply must be read with the English voice (ST-9).
5. Repeat with announcing off: one "Sela sedang menulis…" and one "Balasan selesai.".
6. Press Stop during a slow reply (test double): "Balasan dihentikan sebelum ditampilkan", focus in the text area, no reply text anywhere.
7. Trigger the crisis fixture (synthetic text from the safety test vectors, in demo only): only "Bantuan ditampilkan di bawah pesanmu." is heard (ST-12, ST-13); from the text area, Shift+Tab reaches the pause line and "Ke bantuan" first (ST-20); then navigate the panel by heading and Tab. Close it: the status line, and the pause line with "Lihat semua bantuan". Send another message while paused, then trigger a second match: the condensed panel. Repeat once while scrolled up and once with a magnifier: the new-content button names the help (ST-24).
8. Trigger the `elevated` and `crisis` risk fixtures of the test double (ST-15, ST-16), and the guard-rejection fixture (ST-17).
9. Use "Kurang tepat?".
10. Ask for a reflection: only "Sela menangkap N hal di bawah balasan." is heard (ST-14). Repeat while a long reply is still being read, and record whether the line was dropped. Confirm, change and remove an item.
11. End the conversation, once saved and once unsaved.
12. Navigate the timeline by headings.
13. Review a summary; move an item with "Pindahkan".
14. Share it.
15. Revoke it.
16. Open the recipient page in another browser, paste the code in lower case with spaces, and use "Tidak dapat menerima" up to its confirm.

Record what was announced for each step, word for word.

## 8. Definition of done for a screen (accessibility)

A screen is done only when all of these hold:

1. axe passes with the §6.1 configuration in every §6.2 state that applies.
2. Scripted checks S-1 to S-9 pass for it, and S-13 to S-15 where they apply.
3. A keyboard-only run passes, with its journey recorded.
4. A screen-reader run on at least one desktop and one mobile pairing is recorded, with announcements matching the spec.
5. Reflow at 320px, 200% zoom and text size 150% are checked by eye, with screenshots kept.
6. Copy has been reviewed against CONTENT_STYLE §11 in both languages.
7. The status is labelled honestly:
   - "implemented" (code exists);
   - "verified locally" (the checks above passed locally);
   - "verified with assistive technology" (manual runs recorded).

   Never "WCAG compliant" without a full audit.

## 9. Known exceptions, risks and open questions

| Item | Status |
|---|---|
| The bottom bar sits visually at the bottom but before `main` in the DOM | Deliberate: one reading order on every layout, bypassed by the skip link (1.3.2 reviewed) |
| The fixed help strip in short viewports and while typing in the room (`min-height: 44px` control with 6px around it, growing with its text; about 56–95px) | Deliberate safety exception (D-036), covered by `scroll-padding` from its measured height (2.4.11) and checked at 320×256 and 320×180. Above a third of the viewport height it returns to the page flow (outside the room's typing layout); this reading of "always visible" is pending PM confirmation |
| Typing at 150% text with the keyboard open | Four large transcript lines, a two-line field, Kirim and the help strip do not fit on a 230–300px visual viewport; the composer joins the page flow and the person reads by scrolling with nothing covered (ST-11, S-14). Owner testing with people who use large text checks it |
| The 12-hour absolute session limit and the recipient's share expiry | The 12-hour limit is treated under the 2.2.1 essential exception with a warning and loss-free renewal; the share expiry is at least 24 hours (20-hour exception) and has a static notice near its end; the recipient session and the unsaved-conversation hold warn and extend. Pending the auditor |
| A reflection-card status line arriving while a reply is still being read | May be cut off on VoiceOver iOS or TalkBack; ST-14 measures it, and the card stays reachable by heading and in Detail |
| Safari and `scroll-padding` during focus navigation | Unconfirmed; S-5 runs in WebKit, with a `scrollIntoView` fallback in the room if needed |
| The pattern-view data table may scroll in two dimensions at 320px | Allowed by the 1.4.10 exception for content that needs a two-dimensional layout; it is in its own focusable region with a caption |
| Neutral tab titles (planned, opt-in) | A user-chosen alternate. The default titles conform to 2.4.2 |
| `aria-busy` support varies across screen readers | The post-release pattern never relies on `aria-busy`: no partial text exists, and the log is `aria-live="off"`. The manual tests in §5.1 decide |
| Browser speech recognition may send audio to the browser vendor | Disclosed before opt-in (VO-2). Provider terms are pending verification |
| iOS Dynamic Type does not change web text sizes by default | Sela's own text-size setting covers it. Pending a check of whether `font: -apple-system-body` should map the base size on iOS |
| A JAWS licence may not be available | NVDA with Chrome replaces it, and the gap is recorded |
| No real users with disabilities have tested Sela yet | Recorded as a pilot-readiness gap (brief §13). Agent reviews do not count as user research |
