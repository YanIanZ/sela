## §G Goal

**v3 (user-confirmed, owner brief v3 §1; D-026).** Sela, *A little space to feel heard* / *Ruang sejenak untuk didengar*, continues Dengar.in as a real-use health and wellbeing app in Indonesian and English for people aged 15 to 50 and over. The core experience: "Aku memiliki ruang untuk bercerita, memahami kembali pengalamanku, dan membawa konteks yang kupilih ketika mencari bantuan" (I have a space to tell my story, understand my experience again, and bring the context I choose when I look for help).

- **Listening is the core.** A person starts talking without a long profile, gets replies that fit the context, is never pushed toward a solution and can correct how Sela understood them (V26).
- **Continuity under the user's control.** Personal notes ("Catatan pribadiku"), check-ins, memory and a timeline across sessions, kept only when the user chooses (V27–V29).
- **Help on the user's terms.** When they want to, the user prepares a sourced "Ringkasan untuk konsultasi", shares only what they select with someone they invite, stops further access, and keeps reflecting after the consultation. Seeking a professional is never required.
- Sela is not a diagnosis, treatment, triage, telemedicine or therapy service (C23). Synthetic data is for tests, evaluation and the demo only (C24).

Definition of done (user-confirmed, brief §15): the user can tell their story and get a relevant reply; choose storage; see and correct personal context; open a timeline; prepare a sourced consultation summary; control sharing; stop further access; export and delete data; continue reflecting after a consultation; use Indonesian or English; and complete the main flows with different accessibility needs. The project is not done while a main flow is mocked, the frontend is unreviewed or an important integration is unverified.

Under 15 is refused.
- C20 User-confirmed (brief §5) and PM decision (D-037): **no engagement pressure.** No streaks, points, levels, badges, quests, guilt notifications or push notifications in the pilot. Optional neutral reminders only if the user turns them on (not in pilot scope). Continuity is a calm history, never a score. Any look back over a period (the weekly reflection, after the pilot, backlog S-053) is computed only from that period's real records, in the user's language, without scores or percentages, and says whether rules or AI wrote it (feature matrix DX-11). No design that exploits vulnerability.
- C21 User-confirmed (brief §2) and PM decision (D-033): **content separation.** Public content (reading library, help directory), personal data (owned by one user, linked by ownership and consent), community content (none in the pilot), demo data (synthetic, demo environment only, labelled) and the research corpus (a separate store, never linked to any user's history) stay apart. Evaluation datasets (synthetic and labelled, in `eval/`, `internal/fixtures/` and `data/research/corpus/eval_fixtures/`) and training datasets (none exist; any proposal must pass the fine-tuning gate, backlog S-229, D-048) are further separate stores and are never derived from personal data (brief §9). Another person's story or a public article is never copied into a user's history; a reading item may be bookmarked by reference.
- C22 User-confirmed (brief §7) and PM decision (D-039, D-041, D-042): **honest terms.** "Catatan pribadiku" / "My personal notes" and "Ringkasan untuk konsultasi" / "Summary for a consultation". Never "rekam medis", "diagnosis", "hasil pemeriksaan" or "assessment result". Summaries say they are the user's own notes, prepared with AI help where that applies. A sent or opened share is not care. Recipients are people the user invites; their identity is not verified and is labelled so. No partnership, booking, directory of verified professionals or verified professional note is claimed while none exists. No invented story, count or testimonial is presented as real; any example is labelled as an example (feature matrix DX-07).
- C23 User-confirmed (brief §11) and externally sourced (UU 17/2023 Pasal 172 and 312, PP 28/2024 Pasal 558; read 2026-10-26, not legal advice): **no clinical claims or telemedicine.** Sela supports wellbeing and preparing for help. A crisis match never erases what the user wrote and never navigates away: inline verified help and a link to Immediate help appear, AI generation for that conversation pauses until the user chooses to continue after seeing help, and the text is kept only if the storage choice allows. Journal and check-in entries that match are saved (with storage on) and shown with support, never refused. Second safeguards beyond the lexicon: an always-visible "Butuh bantuan sekarang" / "Need help now" control, Quick exit, the generator's structured risk flag that can only raise the route, the verifier's `safety_signal` issue, and user review of anything shared. Crisis support never waits for a model. Sela never contacts anyone automatically.
- V39 (new, D-044) **Verified help resources.** Only entries verified from official sources are shown, each with source, verification date and a re-verify-by date that the server enforces; a stale entry is flagged, never shown as current. Teen entries need the same verification; the unverified KPAI WhatsApp contact is not shown. No number or service is invented. One catalogue serves every surface.
- V40 (new, brief §7) **Export.** The user can export all their data at any time as readable (HTML, Markdown) and structured (JSON `sela-export/1`) files with provenance, versions and dates. User text is escaped; every export is audited; password, code and token hashes and keys are never exported; the export says downloaded copies cannot be recalled.
- V41 (new, ADR-0003 §9) **Data minimisation for AI providers.** A provider receives only the text segments its task needs, with contact details and names the user marked private replaced by placeholders, per-request span ids and no account, user, session or database identifiers. A conversation the user did not save is never sent for memory. Logs hold metadata only (V12).
- V42 (new, D-046) **Environment separation.** Development, test, demo, staging and production are separate. Production refuses the memory store, test doubles, demo fixtures, insecure cookies and missing secrets. Demo and staging hold synthetic data only. The demo shows a synthetic-data banner and really runs every feature; its AI uses live providers on synthetic data or labelled test doubles (D-046), and test-double output is labelled, never presented as live (V35). ADR-0002 §12 and the `internal/config` guard (committed in `0ff3341`) currently refuse the test double in the demo, which is narrower than D-046; D-046 governs, and the two are being aligned with it ([conflict matrix](docs/status/CONFLICT_MATRIX.md#documentation-and-contract-follow-ups-open) row 52). Demo data never appears in production, and production data is never copied to another environment.
- V43 Retired (D-060) **Dictation test doubles.** The ASR route and `SELA_ASR_MODE` were removed with the text-only decision; no dictation test double exists. V42 still governs the LLM test double.
